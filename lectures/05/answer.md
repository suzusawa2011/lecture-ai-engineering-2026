- 検索だけを実行して見つかったページと、その本文で確認できたこと：`uv run python -m app.retrieval "LoRA QLoRA 違い"` の結果、1位「LoRA と QLoRA ：大きなモデルも GPU 1 台で調整できる」（p.52）、2位「PEFT ：モデル全体ではなく、一部だけを学習する」（p.51）のほか、p.60・p.47・p.61 が返った[cite: 17]。p.52とp.51の本文から、元の重みを固定して差分（低ランク行列）を学習するLoRAと、元の重みを4bitに圧縮するQLoRAの違いを確認できた[cite: 12, 17]。

  - ベクトル検索：`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を1回呼び出し、モデル応答は2回。
  - Tree：`browse_tree({})` → `browse_tree({'node_id': 'lec02-main'})` → `browse_tree({'node_id': 'lec02-main-s045'})` → `browse_tree({'node_id': 'lec02-main-p052'})` と階層をたどり（p.52の本文717文字を取得）、モデル応答は5回[cite: 20, 22]。
  - Graph：`search_graph({'query': 'LoRA QLoRA 固定 学習 第2回'})` を1回呼び出し、モデル応答は2回[cite: 24, 25]。
- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：今回の単一ページ（第2回 p.51〜52）で完結する質問ではいずれの方式でも必要な根拠に到達できた[cite: 12, 26]。一方で、検索結果（上位5件）には質問に直接関わらない演習案内ページ（p.60, p.61）や別の研究比較ページ（p.47）も含まれており、検索件数やノイズの扱いには注意が必要だと感じた[cite: 16]。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：短時間で低コスト・少トークン（入力3,027 tokens・3.45秒・$0.001376）で必要なページに到達できるベクトル検索（基本RAG）が、今回の講義資料Q&Aの基本構成として扱いやすいと感じた[cite: 16, 18]。比較条件の限界として、全文投入だけ対象範囲が全9資料・438ページと広く、Tree実行時のみモデルが`gemini-3.1-flash-lite`になっている点、また単一質問（1回ずつ）の実測であるため複数質問や複数回試行でのばらつきは未検証である点がある[cite: 11, 26, 35]。
- 気づき・疑問：同じ正答にたどり着いても、方式によって入力トークン数（3,027〜117,025 tokens）、推定コスト（$0.001376〜$0.035720）、応答回数・所要時間（3.45秒〜24.42秒）が大きく異なることを体感できた[cite: 15, 18, 21, 24, 27]。Tree探索は目次を段階的にたどる分だけモデル応答回数と時間がかかったが、階層構造が明確な資料でどこまで効率的に辿れるかは質問の種類によって変わりそうだと感じた[cite: 20, 21]。

- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：

- 気づき・疑問：質問によっては上位2件でも十分な根拠が取れる一方、検索クエリの言い回しや複数ページ参照が必要な質問では `RAG_TOP_K = 2` だと根拠不足になる可能性があるため、用途や質問の複雑さに応じた件数設計と検索結果の確認が重要だと感じた[cite: 16, 26, 31]。
